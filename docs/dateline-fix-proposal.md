# 俄罗斯地图撕裂问题分析与解决方案

## 问题现象

进入俄罗斯等跨日期变更线的国家地图后，地图被撕裂到屏幕两侧，或者缩小时出现多个重复的地图并排显示。

## 问题根因

俄罗斯经度范围约 **27°E → 180° → -169°W**，跨越了 180° 日期变更线。

当前代码做了坐标 shift（负经度 +360，如 -169° → 191°），试图让数据在坐标上连续。但这在 MapLibre 中无效，因为：

- **`renderWorldCopies: false`**：MapLibre 只渲染 [-180°, 180°] 范围，超出 180° 的坐标（如 191°）**直接不显示**，导致楚科奇等远东地区消失
- **`renderWorldCopies: true`**：MapLibre 允许无限横向平铺，缩小时会看到多个重复的俄罗斯

所以坐标 shift 方案**本质上不可行** — 它只是把「撕裂到两侧」变成了「右半截消失」。

## 方案对比

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| A. `renderWorldCopies: true` + minZoom 限制 | 保持默认渲染，但限制最小缩放级别不让用户看到重复 | 简单，坐标不需任何处理 | 俄罗斯这类巨大国家 minZoom 需要设很高才看不到重复，可能导致无法看到全貌 |
| B. `renderWorldCopies: true` + maxBounds 框定 | 允许多份渲染，但用 maxBounds 把可视区域锁定在一个世界宽度内 | 用户无法滑到重复区域 | maxBounds 跨日期线时 MapLibre 有 bug（[issue #1298](https://github.com/maplibre/maplibre-gl-js/issues/1298)），且限制拖拽自由度 |
| **C. 不 shift 坐标 + `renderWorldCopies: true` + 动态 minZoom（推荐）** | 保持原始坐标不变，`renderWorldCopies: true`。根据国家跨度计算一个 minZoom，使得在该 zoom 下屏幕宽度刚好不超过 360°（即看不到第二份地图） | 数据零处理；所有国家都能正确显示；自由缩放拖拽 | 超大国家（俄罗斯）的最小缩放会受限，但仍可看全 |

## 推荐方案：C

### 核心原理

屏幕在某个 zoom 级别下能显示的经度范围 ≈ `360 / 2^zoom`：

| zoom | 可视经度范围 |
|------|-------------|
| 0    | ~360°       |
| 1    | ~180°       |
| 2    | ~90°        |
| 3    | ~45°        |

只要 `minZoom` 设置成让屏幕宽度 < 360°，用户就**永远看不到第二份世界**。

对于所有国家地图场景，`minZoom: 2` 就足够了 — 没有任何国家需要用户缩小到能看到 180° 以上的范围。zoom=2 时屏幕约显示 90° 经度，远小于 360°，不会出现重复。

### 具体改动

1. **删除** `shiftCoordinates` 函数和所有坐标 shift 逻辑
2. **删除** `renderWorldCopies: false`（去掉该配置项，默认就是 `true`）
3. **设置** `minZoom: 2`（防止看到重复世界）
4. **所有国家统一用 `fitBounds`**，包括俄罗斯 — 对跨日期线国家，用 `map.jumpTo` 到计算好的中心点 + 合适的 zoom
5. 跨日期线国家的中心点用**加权平均**（负经度先 +360 再平均，结果 >180 再 -360 还原）

### 预期效果

- 俄罗斯：完整显示在屏幕中央，不撕裂、不重复
- 普通国家：行为不变，`fitBounds` 自动定位
- 用户可自由缩放拖拽，最小 zoom 为 2（足够看到任何国家全貌）
